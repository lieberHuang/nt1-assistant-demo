# NT1阵发性睡病助手 · 眠宝功能 Demo

按提供的 UI、PDF 与后续确认实现的本地 HTML 项目。疾病名称统一为 **NT1阵发性睡病**，问答、文章、申请和电话均使用演示内容。采用 HTML、CSS、原生 JavaScript，无前端构建或第三方依赖。

## 在线演示

外网地址：https://lieberhuang.github.io/nt1-assistant-demo/

在线版的说明、聊天、申请和病历保存在访问者自己的浏览器，不会读取或同步作者本地说明。说明可保存、刷新恢复和导出；桌面拍照需浏览器授权相机，手机可调用系统拍照入口。

本仓库通过GitHub Pages从`main`分支根目录发布，推送更新后自动部署。`.local/`中的本地说明、原始需求附件和用户浏览器数据未上传。

## 启动

在本项目目录安装 Node.js 后运行：

```sh
npm start
```

打开 **http://127.0.0.1:8876/**。重启电脑后需重新执行启动命令。端口占用时可执行 `PORT=8877 npm start`。推荐通过本地服务访问，以使用说明文件保存和相机拍照；直接打开 `index.html` 可体验基础功能，但说明只保存在浏览器，相机和媒体存储支持取决于浏览器策略。

## 本次更新

1. **健康科普**：首页点击后，先在对话中展示三篇推荐文章；列表底部“查看更多”在聊天中展开完整文章列表，支持分类与全文阅读、收起与展开。
2. **眠宝陪伴**：参考网站中的小绵羊用于首页欢迎、助手消息头像、文章阅读和病历夹等场景。
3. **援助申请**：创新支付详情中的“申请新的援助”在同页开始，在聊天中逐步填写申请方式、姓名、地区、联系号码、直付用药数量，并上传材料、核对提交。后报销须提供处方和发票。支持驳回后的补件。申请中点击其他功能会提示暂停并保留资料；再次进入先询问继续填写或重新填写。
4. **病历夹**：替代首页“直付药房”。病程卡片仅提供上传图片、使用相机、上传文件三种入口，不提供文字或语音新增入口。收到的资料以卡片展示，保存后可查看时间线、放大图片和下载文件，底部输入框用于普通咨询。
5. **会话快捷按钮**：输入框上方可左右滑动的“创新支付 / 记录病程 / 语音病历 / 用药记录 / 真人客服”，仅在已开始的会话中显示。首页和尚未发送消息的空会话隐藏。
6. **用药记录**：在聊天卡片内填写药品名称、时间、可选用药情况和备注，选择已服用／漏服／暂停状态后一次保存；已有记录也在同一卡片内修改。

病程每条最多8份附件，其中图片最多4张，单个文件最多10MB；图片会缩小压缩。文件支持图片、PDF、Word（doc/docx）与TXT，不接受音频。相机照片自动作为图片加入当前病程，保存前可预览。旧版已保存的文字和音频可继续查看，不清除历史数据。

## 建议体验

- 点击“健康科普”，查看聊天文章列表，再点“查看更多”和文章标题。
- 点击首页“创新支付”，在通过的演示订单底部选择“申请新的援助”，跟随眠宝填写；没有图片时可使用演示材料。
- 点击“病历夹 → 记录新的病程”，在聊天卡片中上传图片、拍照或添加文件后，点击聊天中的保存按钮。
- 在会话中点击“用药记录 → 记录一次用药”，保存后查看列表。
- 右侧“演示场景”可切换入组和订单状态；窄窗口通过手机内“演示”按钮打开。头像在聊天中展开患者档案、历史会话和福利订单。

## 保存位置与重置

- 患者场景、订单、会话及当前正在填写的资料：当前浏览器的 localStorage。
- 已保存病程、用药记录与媒体：当前浏览器的 IndexedDB（`nt1-care-records-v1`）。
- 左侧说明：草稿在浏览器；点击“保存说明”或在编辑区按Cmd/Ctrl+S后，经本地服务写入 `.local/notes.json`。刷新、重启服务、另一浏览器访问同一服务都可读取；多人编辑以最后保存为准。
- 说明可导出文本；窄窗口点击左下“编辑演示说明”。
- 左侧“清空聊天记录”清除本浏览器已有会话，保留说明、已保存病程、用药、订单与未完成援助申请；清空后返回首屏。
- “重置演示数据”会清除本浏览器的患者演示、会话、病程、用药及媒体，保留左侧说明。浏览器数据不会跨设备或跨浏览器同步。
- `file://`、`localhost`、`127.0.0.1`及不同端口具有不同浏览器存储；请固定使用同一地址体验。
- 会话超过3天未互动创建新段，仅保留近12个月。初始化样例会话用于历史展示；刷新会恢复最近的实际操作会话。

手机屏幕为402 × 874逻辑画布，对应1206 × 2622屏幕比例，机框另外增加边框。[Apple iPhone 17规格](https://www.apple.com.cn/iphone-17/specs/)。

## 演示内容与正式接入

问答与六篇文章展示交互及资料整理流程，不提供药品选择、剂量调整或诊疗建议。正式疾病科普、FAQ、项目政策需由项目和医学团队提供并审核。虚构患者、福利金额、处方、发票、订单和电话均不产生真实支付、投保、理赔或拨号。

图片不进行OCR或真实性校验；援助条件、统一申请资格、服务端幂等、材料归属和审批接口未接入。桌面相机权限需由用户在浏览器授权；图片与文件保存在当前浏览器，清理站点数据会删除。请用演示资料体验。

眠宝图片来源为用户指定参考网站：[小绵羊眠宝患者服务](https://lieberhuang.github.io/mianbao-patient-service/)，使用其 `assets/mianbao-lamb.webp` 与 `assets/mianbao-doctor.webp`，本地保存于assets目录。正式对外使用前应由项目方确认素材授权。

## 已保留的流程改进

- 眠宝提供当前步骤帮助、内容接收确认、相机资料接收和保存／提交结果卡片。选择每日状态后直接保存并在聊天中反馈。
- 普通咨询未发送文字可保留。支持“记录用药”“打开病历夹”“看看健康科普”进入相应流程；普通问答不自动进入病程填写。
- 已保存病程和用药支持修改原记录。字段修改可取消，可选项可清空；申请资料可逐项修改，切换申请方式保留基本信息。
- 图片和文件批量处理失败整体回退，替换申请材料不改变历史图片。
- 历史订单不能绕过其他审核中申请；无效订单链接明确提示，缺失材料和初始化示例材料分别展示。

历史走查见[流程走查与眠宝交互改进.md](流程走查与眠宝交互改进.md)，当前验证范围见验证说明。原需求中待确认的状态规则见业务评审。

## 2026-10-14 语音病历

- 新入口位于快捷栏“记录病程”旁，病历夹的新建区也提供同类入口。全部在聊天卡片内完成，无二级页面。
- 语音转文字使用浏览器SpeechRecognition（STT），不是TTS朗读；识别语言为中文。开始后实时显示转写，停止后等待最终结果再自动整理，也可手工修正并点击“完成输入并整理”。单次最多2分钟，原文最多2000字。
- 按用户确认，大模型步骤先以本地演示整理完成，结果明确标注“演示整理”，没有连接真实大模型。根据原文整理患者自述，提取发生时间、症状与表现、频次与持续、场景与影响、用药情况，信息标红；保留否定表述，不补充未提及的事实或诊断。
- 不支持语音识别、网络失败或拒绝麦克风时，可手工输入原文，或用空白卡片中的“使用示例转写”体验。示例不会覆盖已有原文。
- 修改原文会使旧整理结果失效，须重新整理再保存。保存同时保留原文和整理结果，在病历夹可筛选语音病历、回看和修改，修改更新原记录。
- 切换其他功能、发送普通问题、清空聊天或离开页面停止识别；迟到的识别或整理结果不会重新打开卡片。刷新保留当前原文和已整理结果，麦克风不会自动开启。

语音识别的可用性取决于浏览器和其识别服务；部分Chrome识别依赖联网服务，不能视为离线或仅本地音频处理。[SpeechRecognition文档](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。本轮识别流程测试使用可控的识别事件模拟，未验证所有浏览器的真实中文识别准确率。语音病历只保存文字，不保存此次原始录音。


首页补充：首屏功能卡片改为五个，依次为创新支付、病历夹、语音病历、健康科普、联系客服；语音病历直接打开原有聊天卡片流程。五个入口同排展示，适配模拟手机画布。
